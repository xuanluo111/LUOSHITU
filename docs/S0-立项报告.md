## 3. 关键架构决策请求（本报告最重要的一节）

### 决策 ①：QuickJS 运行时的形态 —— **已确认：A 静态内嵌**

现状冲突：
- 提示词红线禁止"安装未知应用"权限，而插件安装机制需要 `REQUEST_INSTALL_PACKAGES`（`app/src/main/AndroidManifest.xml:13`）且安装时系统必然弹窗；
- 插件默认从 GitHub 下载，老人机/国内网络不可达 ⇒ **.js 源与"JS-over-jar"首启大概率失败**，正好踩中 10.4"点播主路径失败"；
- 纯 `csp_` jar 源**不依赖插件**（DexClassLoader parent 指向宿主即可），本次实测配置 52 个源全是 type:3，不受影响。

三个选项：

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | 把 quickjs 模块**静态编回宿主 APK**：`app` 增加 `implementation project(':quickjs')`，改造 `RuntimeModule`（catvod，1-2 处）允许 QUICKJS 走内置 entry（绕开 "implementation is bundled in the host" 守卫），移除插件下载/安装路径与对应权限 | 与上游 loader 层小幅分叉（登记映射表，2.3 纪律）；体积 +（quickjs native ≈ 数 MB，60MB 上限内）；S1 必须做加壳 jar + JS 双冒烟 |
| B | 保留插件架构 | 违反权限红线；首启依赖 GitHub；老人机弹安装窗 ⇒ 不可接受 |
| C | v1.0 不支持 JS 源（只保 csp_ jar + CMS） | 最省事，但违反提示词 3.1/3.2（drpy2 契约为 MUST）；若你接受"我方配置不使用 js 源"可作降级预案 |

### 决策 ②：新增代码语言 —— **已确认：A 新增 Kotlin、存量 Java 不动**（kotlin-android 插件与 stdlib 为"不新增依赖"的登记例处）

### 决策 ③：SDK 版本 —— **已确认：minSdk 24→28，targetSdk 维持 37**

### 决策 ④：二维码导入 —— **已确认：后置**（随 S6 删除 ScanActivity + CAMERA 权限）

## 6. jar/JS 类加载与 R8 keep 审计（3.11-A/B、10.12）

**类加载/反射全量点**：`JarLoader.java:117,125,138,183,217,224-242,250,262,276,282`；`BaseLoader.java:58,195`；`JsLoader.java:24,97-106`；`SpiderTestSession.java:298,312`；`RuntimeModule.java:52-54,154,166-189,546-559`。

**keep 规则现状**：
- `catvod/consumer-rules.pro:1` `-keep class com.github.catvod.** { *; }` ⇒ **jar 侧跨 classloader 依赖的宿主契约（Spider 基类 public 字段 siteKey/net/local/js/dialog、SpiderNull、OkHttp/Net/Local、utils）全量保留**，10.12-A 的前提已被基座满足；
- `app/proguard-rules.pro:4` bean 全保（Gson）；`:6-9` keep `WebActivity.openWeb/getUserAgent`（jar/JS 反射入口）；
- `runtime/proguard-rules.pro:3` `com.fongmi.quickjs.** { public *; }`（插件构建 `-dontobfuscate`）；
- 缺口评估：**未发现加壳 jar 所需宿主类的 keep 缺口**。quickjs consumer-rules 的单层通配弱点仅在插件构建中出现，决策①A（静态内嵌）后须把 `runtime/proguard-rules.pro` 的规则并入 app 级（S1 验证项）。

**结论**：A44（release 可用源数 ≥ debug）的静态前提成立，但 S6 闸门仍须真机 + 真实配置重跑逐源真调用（提示词 10.12-3）。

**10.12-1/2 的我方新增**：`SiteHealthProbe` 必须在 `Init.init` 之后以 `Proxy.proxy(act=home/category/detail)` 真调用判定（`JarLoader.getSpider` 的 computeIfAbsent 需可失效重算——我方封装层处理，不改 catvod）；"解密未就绪"与 SpiderNull 区分，重试不缓存。
