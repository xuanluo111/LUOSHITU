## 3. 关键架构决策请求（本报告最重要的一节）

### 决策 ①：QuickJS 运行时的形态 —— **已确认：A 静态内嵌**

现状冲突：
- 提示词红线禁止"安装未知应用"权限，而插件安装机制需要 `REQUEST_INSTALL_PACKAGES`（`app/src/main/AndroidManifest.xml:13`）且安装时系统必然弹窗；
- 插件默认从 GitHub 下载，老人机/国内网络不可达 ⇒ **.js 源与"JS-over-jar"首启大概率失败**，正好踩中 10.4"点播主路径失败"；
- 纯 `csp_` jar 源**不依赖插件**（DexClassLoader parent 指向宿主即可），本次实测配置 52 个源全是 type:3，不受影响。

三个选项：

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | 把 quickjs 模块**静态编回宿主 APK**：`app` 增加 `implementation project(':quickjs')`，改造 `RuntimeModule`（catvod，1-2 处）允许 QUICKJS 走内置 entry（绕开 "implementation is bundled in the host" 守卫），移除插件下载/安装路径与对应权限 | 与上游 loader 层小幅分叉（登记映射表，2.3 纪律）；体积 +（quickjs native ≈ 数 MB，60MB 上限内）；S1 必须做加壳 jar + JS 双冒烟 |
| B | 保留插件架构 | 违反权限红线；首启依赖 GitHub；老人机弹安装窗 ⇒ 不可接受 |
| C | v1.0 不支持 JS 源（只保 csp_ jar + CMS） | 最省事，但违反提示词 3.1/3.2（drpy2 契约为 MUST）；若你接受"我方配置不使用 js 源"可作降级预案 |

### 决策 ②：新增代码语言 —— **已确认：A 新增 Kotlin、存量 Java 不动**（kotlin-android 插件与 stdlib 为"不新增依赖"的登记例处）

### 决策 ③：SDK 版本 —— **已确认：minSdk 24→28，targetSdk 维持 37**

### 决策 ④：二维码导入 —— **已确认：后置**（随 S6 删除 ScanActivity + CAMERA 权限）

| 上游已确认此问题：Issue #764（2026-10-21）枚举"45 个尚未公开的 media3 类"，结论"目前无法从源码构建"；作者 FongMi 答复（10-23）："**請善用 ai 補齊功能**" | https://github.com/FongMi/TV/issues/764（已关闭） |
